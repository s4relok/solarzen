Вот ясная инструкция для репозитория с игрой.

**Цель**

Проект игры должен уметь собирать полностью статическую версию в папку `dist/`, которую можно просто скопировать на `celticspear.com` и открыть по URL вида:

```text
https://celticspear.com/hobby/<game-slug>/
```

**Что сделать в проекте игры**

1. Убедиться, что есть команда сборки:

```bash
npm run build
```

Она должна создавать папку:

```text
dist/
```

Внутри должны лежать готовые файлы:

```text
dist/index.html
dist/assets/...
dist/*.js
dist/*.css
```

2. Настроить относительные пути.

Важно: игра будет жить не в корне домена, а в подпапке. Поэтому в сборке не должно быть жестких путей от корня вроде:

```html
<script src="/assets/game.js">
<link href="/assets/style.css">
```

Лучше:

```html
<script src="./assets/game.js">
<link href="./assets/style.css">
```

Если это Vite, в `vite.config.js` нужно:

```js
export default {
  base: './',
}
```

Если другой сборщик, аналогично выставить public/base path в относительный режим.

3. Проверить локально именно собранную версию.

После сборки открыть `dist/index.html` или поднять простой статический сервер из `dist/`:

```bash
npm run build
npx serve dist
```

И проверить, что игра работает без dev-server магии.

4. Не привязывать игру к своему домену.

В коде игры не должно быть ожиданий, что она открыта именно с GitHub Pages, localhost или отдельного домена. Она должна спокойно работать из подпапки сайта.

5. Дать игре стабильный slug.

Например:

```text
hobby/my-game/
hobby/puzzle-lab/
hobby/tiny-rogue/
```

Slug лучше выбрать один раз и потом не менять, если кто-то уже мог получить ссылку.

**Как будет происходить публикация**

В проекте игры:

```bash
npm run build
```

Потом содержимое `dist/` копируется в сайт:

```text
F:\Projects\celticspear.com\hobby\<game-slug>\
```

После этого в репозитории `celticspear.com` коммитится уже готовая статическая версия игры.

То есть проект игры отвечает за исходники и сборку, а `celticspear.com` хранит опубликованный артефакт. Это самый простой и надежный вариант для текущего сайта.
